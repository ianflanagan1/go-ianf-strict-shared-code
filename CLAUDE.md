# go-ianf-strict-shared-code

The code shared by every project on go-ianf-strict-baseline: adapters under `adapters/`, and value code under `values/`. `README.md` describes each package.

## Decisions made

- `values/email` is the value object to copy when writing another. Its shape: one package for the value; a struct with exported fields, no struct tags and no getters (`LocalPart`, `Domain`); one factory function named for its input (`ParseAddress`) that returns `(T, error)`; unexported functions that each check one part; and a `Text()` method for the written form. It normalises in the factory function so that the shared equality function finds two spellings of one value equal, and declares no `Equal`, no other comparison and no `String`.
- `values/id`'s `RowID` and `PublicID` hold their 16 bytes in an exported `Bytes [16]byte` field, not a `uuid.UUID`, since a value object holds no standard-library or third-party object. The standard library's `uuid` package still parses and prints them inside the package.
- The shared equality function is `core/equality.Equal[T any](a, b T) bool`, and the shared equality assertion is `core/equalitytest.AssertEqual[T any](t testing.TB, want, got T)`, which ends the test with both values. They are core, so they live under `core/`; `values/` stays where it is. `equalitytest` is the only package that programs don't run, and its name says so in place of a test-only marker, which Go doesn't have. `Equal` reads exported fields by reflection and calls nothing the values declare. A pointer or a channel equals only the same address. A non-nil function, and a struct with an unexported field such as `time.Time` or `id.Internal`, equal nothing, themselves included. A nil slice or map equals an empty one. Tests compare values with `AssertEqual`, never `==` on structs or arrays, or `reflect.DeepEqual`. A fast path through `==` for comparable types gave the same answers and no speed-up, so there isn't one.
- A factory function that can fail in more than one way returns an enum-like error type, as `email.AddressError` is: an `int` type with an `Err…` constant for each failure, counted from 1, and an `Error()` whose message holds nothing of the text. A caller finds it with `errors.As` and branches with a `switch` the `exhaustive` linter checks. One that can fail in one way keeps a sentinel, as `values/id` does.
- Value code keeps nothing at package level but constants. A fixed list (`atomRejected()`) and a third-party object built from options (`hostNames()`) come from a function that builds them on each call, and a check over runes stands in for a compiled pattern.
- `values/email`'s tests port php-ianf-strict-shared-code's `EmailAddressTest` case for case: one top-level test for each PHP test method, under the same name, and one named subtest for each text. The PHP cases are the specification.
- `golang.org/x/net/idna` and `golang.org/x/text/unicode/norm` are approved for value code, and no other third-party package is. Both hold their Unicode tables in their own code, so reading them isn't the rulebook's `unicode-data` operation. Reread `idna.go` before raising `golang.org/x/net`'s version: `hostNames()` depends on what each option sets, on `MapForLookup` coming first, and on the tables that the Go version selects.
